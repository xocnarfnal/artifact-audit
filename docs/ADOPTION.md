# Measuring real adoption

Artifact Audit has no telemetry, analytics SDK, phone-home call, or package-side tracking. Measure only public activity and the aggregate data offered by the hosting platforms. Record a date, source, and caveat with each observation; never interpret downloads or stars as unique active users.

- **GitHub stars and forks:** Read the public repository's counts and check whether new forks contain actual usage or contributions. A star is interest, not an installation. [Repository page](https://github.com/xocnarfnal/artifact-audit).
- **Traffic, referrers, and clones:** If the maintainer's repository Insights → Traffic view is available, record unique visitors, referring sites, total clones, and unique cloners, with the short window and platform limitations attached. GitHub's [traffic API](https://docs.github.com/en/rest/metrics/traffic) provides only the last 14 days for clones and needs repository write access; it is not a lifetime unique-user count. Do not publish private referrer details or access credentials.
- **Issues and external PRs:** Count substantive bug reports, questions, and accepted external pull requests; distinguish the maintainer's own work from external contributors. A first reproducible report from another person is more informative than a large unqualified download number.
- **PyPI downloads:** PyPI does not put reliable download statistics on project pages. Its public [BigQuery download table](https://docs.pypi.org/api/bigquery/) can provide time-bounded file-download counts. The [Python Packaging User Guide](https://packaging.python.org/en/latest/guides/analyzing-pypi-package-downloads/) explains the query and limitations: caching, mirrors, automated CI, and historical quality issues distort counts. Query a fixed date range and, where useful, filter installer or version. Do not call raw downloads unique users.
- **Marketplace:** Confirm the Action listing is visible and its version/install snippet is current. GitHub's documented [Marketplace Insights](https://docs.github.com/en/apps/github-marketplace/creating-apps-for-github-marketplace/viewing-metrics-for-your-listing) apply to **GitHub Apps**, not necessarily Actions; do not invent Action installation counts. If GitHub exposes Action-specific visibility or usage data to the maintainer, record its definition and source before reporting it.

Keep a small private or public-in-repository snapshot of aggregate, non-sensitive numbers with dates. Do not add product telemetry or collect user-identifying data to fill a measurement gap. The next meaningful milestone is a real external workflow using the Action or a reproducible piece of feedback, not an artificial target number.
